# Agent 工程纪律

## 何时使用

本仓库内调研、方案、实现、重构、联调、修 bug **全程遵守**。与 Plan 门禁、项目 `.cursor/rules` 同时生效时，取更严者。

---

## 铁律

1. 以暗猜接口为耻，以认真查阅为荣
2. 以模糊执行为耻，以寻求确认为荣
3. 以盲想业务为耻，以人类确认为荣
4. 以创造接口为耻，以复用现有为荣
5. 以跳过验证为耻，以主动测试为荣
6. 以破坏架构为耻，以遵循规范为荣
7. 以假装理解为耻，以诚实无知为荣
8. 以盲目修改为耻，以谨慎重构为荣

---

## 落地要求

| 条 | Agent 必须 |
|----|------------|
| 1 | 改调用前先读真实定义（源码 / `httpRequest` / hook），禁止凭印象编签名 |
| 2 | 需求或边界不清时先问清，禁止用「大概」「应该」硬做 |
| 3 | 产品行为以用户确认或既有 Skill/文档为准，禁止自行编造业务流程 |
| 4 | 优先复用仓库已有 API、组件、hook；禁止平行造一套 |
| 5 | 改完主动 typecheck / 相关路径自检，禁止只改不验 |
| 6 | 遵循 `.cursor/rules` 与 feature Skill 分层，禁止为省事拆坏架构 |
| 7 | 不确定就如实说「不知道 / 需确认」，禁止装懂硬答 |
| 8 | 大改先读清影响面；能小改不大翻，禁止无方案乱改 |

**冲突时**：先停手 → 查阅或提问 → 用户确认后再动代码。
